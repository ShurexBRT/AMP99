# AMP99 v0.2.0-alpha.15

> Closed alpha · docked windows inherit Always on Top

## Summary

Alpha.15 fixes the z-order issue shown in Recording #42: Main could remain above normal windows while a docked Equalizer or Playlist window did not reliably stay in the same Always on Top group after being shown, restored or moved.

## Changes

- Reapplies the native Always on Top group state after EQ/Playlist show and unminimize.
- Reapplies the group state after Main and its docked windows are restored from minimize.
- Reapplies the group state after moving a docked group with Main.
- Keeps Always on Top disabled when the preference is disabled; no forced topmost behavior is added.

## Manual Windows test plan

- [ ] Update from alpha.14 through `Preferences → Check for Updates`.
- [ ] Enable `Always on top` in Preferences, dock EQ and Playlist to Main, then switch focus to Chrome or another normal window; all three AMP99 windows must remain above it.
- [ ] With Always on Top enabled, hide and show EQ; it must return above normal windows with Main.
- [ ] With Always on Top enabled, hide and show Playlist; it must return above normal windows with Main.
- [ ] Minimize and restore Main from the taskbar; docked EQ/Playlist must return in the same topmost group.
- [ ] Move Main while EQ/Playlist are docked; the auxiliary windows must follow and remain topmost.
- [ ] Disable `Always on top`; AMP99 windows must behave as normal windows after show/restore.
- [ ] Confirm independent hide/show, docking, Spotify playback, OAuth and playlist data are unchanged.

## Known limitations

- Spotify Web Playback still depends on Spotify's active-device readiness and Premium account rules.
- This remains a closed alpha release and requires manual Windows QA on the target machine.
